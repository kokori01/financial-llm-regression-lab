# Decision: structured claims, application-owned display text

Status: implemented in application 0.2.0, response contract v2, November 9, 2026.

## Observed problem

The v1 evaluator accepted three independently constructed counterexamples: correct sales fields with a claim of zero sales; correct abstention fields with invented FY2027 sales in prose; and a correct fiscal-prefix sentence followed by a contradictory assertion. All three passed before changes. Three regression tests were added first and failed against that implementation.

The original documentation disclosed that semantic faithfulness was not evaluated, but a case-level PASS still looked stronger than the delivered answer deserved. Disclosure alone did not close the interface weakness.

## Decision

The accepted response now contains only `status`, `value`, `unit`, `period` and `citations`. `period` is structured as basis, year, start and end. Arbitrary text fields are forbidden, including nested extras. An abstention has null value and period, no citations, and a nonnumeric unit.

The evaluator checks these claims against independently reviewed case expectations and evidence. Only a passing result receives `rendered_answer`. The renderer uses the checked response value and unit plus trusted query metadata; it does not silently substitute the gold number. An accepted approximate percentage is displayed as returned. Invalid or unverified responses remain available as raw audit material but receive no approved display text.

Abstention wording is generated by the application: it states that the supplied packet does not support the requested metric/year. A model cannot insert a fabricated result into that sentence.

## Alternatives and tradeoffs

- Keyword or numeric-token scans would misread negation, dates, multiple operands and valid paraphrases. Finding one correct number would not establish consistency of the whole sentence.
- Requiring a canonical model-generated sentence would reject equivalent financial wording and test string copying rather than reliability.
- An LLM judge would add cost, nondeterminism, its own error rate and a validation problem larger than this proof of concept.
- Keeping unrestricted prose while downgrading every result to manual review would avoid overclaiming but leave no fully checked answer at this small component boundary.

The chosen design removes the need to evaluate arbitrary wording. It deliberately changes the API: a response with any `answer` text is invalid whether that text is true or false. This is an interface rule, not an assertion about prose meaning. Downstream consumers use application-rendered text and checked structured claims.

The consequence is narrower functionality: this component no longer accepts open-ended explanations. That is appropriate for the twelve bounded questions, but not a general financial research assistant. Free-text semantic faithfulness remains `not_evaluated` in reports. The project must not describe this change as a general semantic-consistency solution.

## Migration and evidence

C05 keeps its fiscal-versus-calendar interpretation goal, with dates in a structured period instead of an English prefix. The other eleven scenario goals, all source figures, gold values and tolerances remain unchanged. The synthetic responses were mechanically migrated to the new fields while preserving their deliberate defects; their configuration IDs are now `synthetic-baseline-v2` and `synthetic-candidate-v2`.

Prompt IDs changed to `strict-v2` and `explicit-v3`; old IDs are not silently reused. v1 case and fixture files remain alongside the current resources with `_v1` suffixes. Original operational reports are retained privately; the public repository includes the audit probes and reviewed report extracts. Results across different contract versions cannot establish a model regression without holding the contract fixed.

The three original counterexamples now fail. Additional tests insert novel true and false prose into otherwise valid v2 responses, check safe abstention, vary period fields, and confirm that failed claims never receive approved display text. The original twelve replay scenarios still exercise the financial checks rather than simply failing the interface migration.
